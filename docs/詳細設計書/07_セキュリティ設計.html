07 セキュリティ設計

1. 方針

対象 方針
管理画面 管理者1人だけがログインして使う。ログインは Cookie のセッションで保つ
公開サイト ログインなしで使える。お問い合わせフォームは、機械的な送信と大量の送信を防ぐ
入力 画面のチェックは補助とし、API で必ずチェックする
秘密情報 パスワード・トークンはハッシュにするか、git で管理しないファイルに置く
個人情報 必要なものだけを取り、不要になったら削除する。カード番号は扱わない

2. 管理者の認証

項目 内容
管理者 .env の ADMIN_EMAIL の1人だけ（起動時に、ほかの管理者は削除する。06 6.5）
パスワードのハッシュ PBKDF2-HMAC-SHA256、600,000回、ソルトはランダムな16バイト
保存の形 pbkdf2_sha256${回数}${ソルト（Base64）}${ハッシュ（Base64）}
比べ方 一定の時間で比べる（hmac.compare_digest）
パスワードの長さ 8〜128文字
メールアドレス 前後の空白を除き、小文字にして比べる
登録されていないメール ダミーのハッシュで同じだけ計算してから失敗にする（応答の時間で、登録の有無を推測されにくくする）
失敗のメッセージ メールとパスワードのどちらが違うかは言わない（「メールアドレスまたはパスワードが正しくありません。」）
初めのパスワード 起動スクリプトが .env を作るときに、ランダムな16文字（英数字）にして、ターミナルに表示する
忘れたとき .env の ADMIN_PASSWORD を書き換えて再起動すると、その値になる（ログイン中のセッションはすべて無効）

3. セッションと Cookie

項目 内容
トークン ランダムな32バイト（secrets.token_urlsafe(32)）
データベース トークンの SHA-256 だけを保存する（データベースが漏れても、そのままではログインに使えない）
期限 ログインから12時間（使っても延長しない）
Cookie の名前 bt_admin_session
HttpOnly あり（画面の JavaScript から読めない）
SameSite Strict（ほかのサイトから来たリクエストには付かない）
Path /api（API にだけ送る）
Secure .env の COOKIE_SECURE=true のときあり（HTTPS の通信にだけ付く）。本番は必ず true

セッションを無効にするとき:

きっかけ 無効にするセッション
ログアウト そのセッション
パスワードの変更（A-17） その画面以外のすべて
.env のパスワードでのリセット（再起動） すべて
.env の ADMIN_EMAIL の変更（再起動） 古い管理者のすべて（管理者ごと削除）
期限切れ 使えなくなる。行は起動時に削除

4. 試行回数の制限

対象 上限 超えたとき
ログインの失敗 同じ IP から15分に10回 429「ログインの試行回数が多すぎます。しばらくしてからお試しください。」
お問い合わせの送信 同じ IP から10分に10件 429「送信回数が多すぎます。しばらくしてからお試しください。」

数え方は 06 7章です。回数は API のメモリに持つため、API は1つのプロセスで動かします。リバースプロキシの後ろでは、本当の接続元の IP が API に届くように設定します（08 8.4）。

5. ほかのサイトからの不正なリクエストの対策（CSRF・CORS）

対策 内容
SameSite=Strict の Cookie ほかのサイトのページから管理画面の API を呼んでも、ログインの Cookie が付かないので、401 になる
CORS .env の FRONTEND_ORIGINS の接続元にだけ、応答を読む許可（Access-Control-Allow-Origin）を返す。ほかの接続元の JavaScript は、応答を読めない
許可するメソッド・ヘッダー GET・POST・PUT・PATCH・DELETE、Content-Type・Accept だけ

6. 応答ヘッダー

API のすべての応答に付けます（main.py）。

ヘッダー 値 目的
X-Content-Type-Options nosniff ブラウザに、ファイルの種類を推測させない
X-Frame-Options DENY ほかのサイトの枠（iframe）の中に表示させない（クリックジャッキングの対策）
Referrer-Policy strict-origin-when-cross-origin ほかのサイトへ移るときに、URL のパスを渡さない
Cache-Control（/api/ 以下） no-store 個人情報を含む応答を、ブラウザや途中のサーバーに保存させない

画面のファイル（frontend/dist）は API が配信しないので、本番では配信するサーバーにも同じようなヘッダーを設定します（08 8.2）。

7. 入力のチェック

対象 対策
すべての入力 API で必ずチェックする（04・06 2.2）。長さ・件数・数値の範囲に上限を決める
選択肢 shared/contact_options.json などの決まった値だけを受け付ける
URL http://・https:// で始まるものだけ（javascript: などは不可）。LINE の URL は https:// だけ
メールアドレス・色・日付 形式をチェックする
パスの ID 12桁以内の半角数字だけ（ほかは 404）
本文 JSON のオブジェクトでなければ 400
SQL 値はすべてプレースホルダ（?）で渡す。並び順などは決まった候補から選ぶ。検索は instr を使い、ワイルドカード（% _）を解釈しない

8. 表示・出力するときの対策

対象 対策
画面の表示 React で表示する（文字は自動でエスケープされ、HTML として実行されない）。HTML をそのまま埋め込む書き方（dangerouslySetInnerHTML など）は使わない
外部へのリンク 新しいタブで開くリンクには rel="noopener noreferrer" を付ける
CSV 先頭が = + - @ などの値に ' を付け、Excel で数式として実行させない（CSV インジェクションの対策）
メールのヘッダー 件名・差出人名の改行を空白にする（ヘッダーインジェクションの対策）。宛先・返信先はメールの形式に合うときだけ使う
エラー 予期しないエラーの詳しい内容（プログラムの中身）は応答に出さない

9. ファイルのアップロード

対策 内容
ログイン 管理者だけがアップロードできる
大きさ 5MB まで（Content-Length と本文の両方で確認）
種類 ファイルの先頭のバイトで判定し、PNG・JPEG・GIF・WebP だけを受け付ける。スクリプトを含められる SVG は受け付けない
名前 サーバーでランダムな名前を付ける（送られた名前は使わない）
取り出し 名前が決まった形（16進数24桁 + 拡張子）に合うときだけ返す。フォルダをさかのぼる名前（../）は使えない
種類の表示 拡張子から Content-Type を決め、nosniff を付ける

10. 迷惑送信の対策

対策 内容
隠し欄 人には見えない入力欄に値があれば、保存せずに成功として返す（機械的な送信は、ほとんどがここで止まる）
ブロックリスト 登録したアドレス・ドメインからの送信は「迷惑送信」として保存し、新着通知・自動返信を送らない
回数の制限 同じ IP から10分に10件まで。自動返信は入力されたアドレスに送るため、他人のアドレスあてに大量に送られるのも防ぐ

11. 秘密情報の扱い

情報 置き場所 守り方
管理者のパスワード（平文） .env git 管理外（.gitignore）。起動スクリプトが作るときは権限 600。データベースにはハッシュだけ
ログインのトークン ブラウザの Cookie HttpOnly。データベースにはハッシュだけ
SMTP のパスワード settings 表の smtp（メールサーバーへのログインに使うため、平文） 画面・API の応答には返さない（設定済みかどうかだけ返す）。入力欄が空なら変えない。データベースとバックアップの zip に入るので、zip の保管に注意する
Outlook のトークン data/microsoft-oauth.json git 管理外、権限 600、書き込みは一時ファイルからの置き換え。バックアップの zip に入れない
MICROSOFT_CLIENT_ID .env 秘密の値ではない（クライアントシークレットを使わない公開クライアント）が、.env で管理する
データベース data/app.db git 管理外

12. 個人情報の扱い

項目 内容
取る情報 お名前・メール・電話番号・都道府県・年齢（任意）・ご相談内容・お支払い方法の選択（02 4.2）
取らない情報 カード番号など。フォームにも「入力しないでください」と書き、カードの決済は決済サービス会社の画面で行う
同意 「個人情報の取扱い」の全文を最後までスクロールしてから、「同意する」を押せるようにする
保存される場所 inquiries（本体）、inquiry_notes（メモ・返信の本文）、mail_outbox（宛先・本文）、audit_logs（削除したお問い合わせのお名前・メールなど）、estimates・payments・contracts（お客さま名・メール）、login_history（管理者のメール・IP）
削除 管理画面から1件ずつ、または自動削除（06 11章）。お問い合わせを削除したときは、メモ・記録と送信履歴も削除する（※課題 No.1）。操作の記録・ログイン履歴の扱いは ※課題 No.3
持ち出し CSV とバックアップの zip には個人情報が入る。保管と削除に注意する
アクセス解析 手元の確認と管理画面では計測しない。お名前などの個人を特定する情報は送らない

13. 記録

記録 内容 見る場所
操作の記録 管理画面での変更・ダウンロード（06 21章） A-15
ログイン履歴 成功・失敗、入力されたメール、IP、ブラウザの情報 A-15
前回のログイン 1つ前の成功したログインの日時と IP A-02（身に覚えのないログインに気づけるように）

14. 本番で必ず行う設定

設定 理由
HTTPS で公開し、.env を COOKIE_SECURE=true にする ログインの Cookie を暗号化した通信でだけ送る
.env の FRONTEND_ORIGINS を、公開する画面の URL だけにする ほかの接続元から API の応答を読ませない
画面と API を同じドメインの配下にする SameSite=Strict の Cookie を使うため
.env の ADMIN_PASSWORD を推測されにくい値にし、.env を他人に渡さない 管理画面を守る
リバースプロキシの後ろでは、本当の接続元 IP を API に渡す 回数の制限とログイン履歴の IP のため（08 8.4）
画面のファイルを配信するサーバーにも、6章のような応答ヘッダーを付ける 画面のページにも、クリックジャッキングなどの対策をする
必要に応じて、API の説明ページ（/api/docs）を止める 本番では使わないため（止めるときは main.py の docs_url・openapi_url）
