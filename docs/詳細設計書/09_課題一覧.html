2. 詳細

No.1 お問い合わせを削除しても、送信履歴が残る

項目 内容
仕様 お問い合わせを削除したら（管理画面からの削除・自動削除とも）、そのお問い合わせの送信履歴も削除する（2026-10-30 に決定）
今の動き mail_outbox.inquiry_id の外部キーが ON DELETE SET NULL のため、送信履歴の行が残り、お問い合わせとのひもづけだけが外れる。新着通知・自動返信の本文には、お名前・メール・電話番号などが入っている。削除の確認文（「メモや送信履歴も消え、元に戻せません」）とも合わない
影響 「個人情報の取扱い」の「不要になった情報は削除します」が守られない。自動削除を有効にしても、送信履歴に個人情報が残る
直し方の案 お問い合わせを削除する処理（inquiries.delete_inquiry・maintenance.run_retention）で、先に mail_outbox の該当する行を削除する。または、外部キーを ON DELETE CASCADE に変えるマイグレーションを追加する（SQLite では、外部キーを変えるには表を作り直す必要がある）
関係する箇所 04 API-14、05 4.8・5章、06 11.2、07 12章

No.2 領収書の発行日が、印刷のたびに変わる

項目 内容
仕様 発行日は一度決まったら、印刷し直しても変わらない（2026-10-30 に決定）
今の動き 印刷画面（A-09）を開いた日（今日）を表示する。発行日はどこにも保存しない
影響 後日に印刷し直すと、最初に渡した領収書と発行日が違うものになる
直し方の案 (a) 入金日を発行日として表示する（変更がいちばん少ない）/ (b) payments に発行日の列を追加し、初めて印刷したとき（または入金を記録したとき）の日付を保存する / (c) 入金の入力欄に発行日を追加する。どれにするかは未決
関係する箇所 03 A-09、05 4.13、06 14章

No.3 操作の記録・ログイン履歴に保存期間がない

項目 内容
今の動き 操作の記録「お問い合わせを削除」に「#{ID} {お名前} 様（{メール}）」を残す。対応状況の変更・返信などの記録にもお名前が入る。操作の記録とログイン履歴は、自動では削除されない
影響 No.1 と同じく、削除したお問い合わせの個人情報の一部が残り続ける
直し方の案 操作の記録にはお問い合わせの ID だけを残す。または、操作の記録・ログイン履歴を一定期間（例: 1〜2年）で自動削除する
決めること 操作の記録に何を、どれくらいの期間残すか

No.4 見積書の画面で、日付の前後関係のエラーが表示されない

項目 内容
今の動き 有効期限が発行日より前のとき、API はキー body で「有効期限は発行日以降の日付にしてください。」を返すが、見積書の画面（A-06）は body のエラーを表示しないため、上部に「入力内容をご確認ください。」だけが出る
直し方の案 A-06 で errors.body を表示する（保守契約の画面 A-10 と同じ）

No.5 「送信中」のまま残った送信履歴

項目 内容
今の動き 送信の途中で API が止まると、送信履歴が「送信中」（pending）のまま残る。A-13 は送信中の記録に「送り直す」「削除」を出さず、API-46 も送信中の記録の削除を断る
直し方の案 登録から一定時間（例: 10分）たった送信中の記録は、送り直し・削除できるようにする。または、API の起動時に古い送信中の記録を「失敗」にする

No.6 返信の送り直しの後処理

項目 内容
今の動き 返信（API-17）が送れなかったあと、送信履歴から送り直して送れても（API-45）、お問い合わせの記録（種類「メール」）の追加と、未対応 → 対応中の変更をしない
直し方の案 送り直しで送れたメールの種類が reply のときは、API-17 と同じ後処理をする

No.7 サイト内容の、ほかのタブの入力が元に戻る

項目 内容
今の動き A-11 で保存すると、すべてのタブの入力を、保存した時点のサーバーの内容で置き換える。ほかのタブで入力中だった内容は消える
直し方の案 保存したタブの入力だけを、サーバーの内容で置き換える

No.8 収入印紙の注意を出す条件

項目 内容
今の動き お支払い方法が現金で、金額が5万円以上のときだけ、注意を出す
確認したいこと 紙で渡す領収書は、銀行振込で受け取った代金でも、5万円以上なら収入印紙が必要になる場合があるとされています（クレジットカード払いで、その旨を書いた領収書や、PDF をメールで送る場合は不要とされています）。税務署や税理士に確認して、注意を出す条件を決める

No.9 入金一覧 API の説明

項目 内容
今の動き 説明ページ（/api/docs）の説明は「入金の一覧（期間内の合計つき）」だが、期間の絞り込みはなく、合計は検索条件（キーワード）に合う入金の合計
直し方の案 説明を「検索条件に合う入金の合計つき」に直す（routers/admin_billing.py の summary）。期間で絞り込みたい場合は、パラメータを追加する

No.10 ダッシュボードの「今月の入金」

項目 内容
今の動き 入金日が今月1日以降の入金をすべて合計するため、入金日を来月以降にした記録も入る
直し方の案 「入金日が来月1日より前」の条件も加える（dashboard.summary）

No.11 番号の使い回し

項目 内容
今の動き 連番は「同じ年月の番号のうち、いちばん大きい番号 + 1」なので、いちばん大きい番号の記録を削除すると、次に作る記録に同じ番号が付く
影響 お客さまに渡した領収書の記録を削除して作り直すと、同じ番号の領収書が2枚になる
直し方の案 削除しても番号を使い回さない（年月ごとに採番した最大値を保存する）。または、入金の記録は削除ではなく「取り消し」にする

No.12 プロジェクトの README.md

項目 内容
今の動き (1) フォルダ構成と起動手順が C:\Users\document\python（/mnt/c/Users/document/python）を起点に書かれているが、プロジェクトは company フォルダの中にある。(2)「内容を変えたいとき」で、事業者情報は frontend/src/lib/site.ts、料金・よくある質問は content/home.ts で変えると書かれているが、今は管理画面のサイト内容（初期値は shared/site_defaults.json）で変える
直し方の案 README.md を今の構成に合わせて直し、この設計書（docs/詳細設計書/）への案内も加える
